== Uso de Maven

El plugin https://eclipse.dev/m2e/ permite el uso de Maven dentro de Eclipse.

Para importar el proyecto en Eclipse, debe seguir la siguiente ruta:
menu:file[Import > Maven > Existing Maven Project]

Luego de seleccionar el proyecto e importarlo, dentro de `Projects` el
`pom.xml`. Seleccione este archivo y haga click en `Finish`.

Para ejecutar los tests, los pasos son los mismos que con Junit 4, pero
selecciona menu:RunAs[maven test].

Para compilar, menu:RunAs[maven compile] o menu:RunAs[maven build].

Para ejecutar el programa, ejecute el `Main`.

== Diseño

En este TP usamos nuevamente MVP (Model-View-Presenter) para separar la
interfaz gráfica de usuario (GUI) del código de negocio (Modelo).

El proyecto está separado en módulos, cada uno representando cada parte del
diseño de MVP. A su vez, cada módulo está separado en clases, cada una con su
responsabilidad. Además, esta separación permite la reducción de código
duplicado y extensión del proyecto.

Para la GUI utilizamos `JTable` para mostrar los diferentes empleados
ingresados. Estas tablas están ubicadas en diferentes pestañas, cada una
mostrando una información específica:

* *Employees*: muestra los empleados ingresados con su foto de perfil, nombre,
  rol y calificación.
* *Incompatibilities*: muestra los empleados con incompatibilidad.
* *Teams*: muestra el equipo óptimo posible con los empleados ingresados y las
  incompatibilidades existentes.

Para poder ingresar empleados, incompatibilidades y generar el equipo, se
añadió un toolbar con las acciones disponibles.

* *Añadir empleado*: permite añadir nuevos empleados con los datos
  correspondientes, además de una foto de perfil.
* *Añadir incompatibilidad*: permite añadir una incompatibilidad entre dos
  empleados existentes.
* *Generar equipo*: permite generar un equipo dado los requirimientos ingresados
  por el usuario.

Luego de presionar el botón para generar un equipo, se inicia un thread separado
que se llama `SolveWorker` que busca el equipo óptimo utilizando backtracking
gracias a los métodos utilizados en el `TeamSolver`.

Para poder encontrar la solución más óptima, al llegar a una solución en el
cuál dos empleados eran incompatibles, esa solución se "podaba", es decir, se
retornaba para buscar otro empleado.

Luego de que se encuentre un equipo válido, el método busca otro camino que
tenga más calificación. Si no encuentra otro camino, devuelve el equipo válido.

== Dificultades

En general no hubo mayores complicaciones. Particularmente la mayor dificultad
fue en poder mostrar imágenes en las tablas, y cómo reusar estas imágenes en
diferentes tablas para evitar cargar en memoria la misma imagen múltiple veces.
Para eso se utiliza la clase `ImageRegistry`, que permite asociar un empleado
con una imagen, y así poder reusarla en diferentes partes de la interfaz,
cacheando la imagen.

== Cosas a mejorar

Se cumplieron los objetivos principales del TP, pero aún quedaron detalles y
funcionalidades a mejorar y añadir.

Una de ellas es la opción de borrar un empleado específico, o borrar una
incompatibilidad añadida.

Otra funcionalidad deseada es mostrar en pantalla múltiples equipos generados,
en vez de solo un equipo.

La opción de heurística quedó pendiente de implementar, para poder comparar la
solución hecha por el backtracking y la solución hecha por la heurística.

Otra cosa a mejorar la identificación de empleados, ya que actualmente utiliza
el nombre y rol para identificarlos. Hubiese sido ideal poder haber añadido
algún dato único para identificarlos, como un mail o un DNI.
